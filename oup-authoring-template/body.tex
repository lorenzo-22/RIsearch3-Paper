\section{Introduction}

Intermolecular RNA--RNA interactions underpin a wide range of regulatory
mechanisms, and predicting them at genome- or transcriptome-wide scale is a
recurring task in RNA biology. The problem is particularly demanding for
synthetic small interfering RNAs (siRNAs), where unintended off-target
binding can confound RNAi knockdown experiments and limit therapeutic
application.

RIsearch2~\citep{alkan2017risearch2} is a widely used tool for large-scale
screens of near-complementary RNA--RNA interactions: it combines a
suffix-array index of the target with a seed-and-extend dynamic-programming
step that uses the simplified energy model introduced by
RIsearch~\citep{wenzel2012risearch}. The companion siRNA off-target pipeline
distributed alongside RIsearch2 turns these predictions into per-transcript
binding probabilities and a transcriptome-wide off-targeting potential
through a partition-function model that integrates transcript abundance and
binding-site accessibility.

Despite the algorithm's continued relevance, the software ecosystem has aged
less well: RIsearch2 ships as a C source tarball with a custom Makefile; the
off-target pipeline is written in Python~2.7, long past end of life; and
neither component exposes a library API suitable for embedding in modern
Python-native analyses.

We present \textbf{RIsearch3}: a Rust reimplementation of the RIsearch2
algorithm with parity-tested behaviour, a redesigned command-line interface,
and PyO3 Python bindings that expose search results as native Polars
DataFrames. Alongside the core, we release a rewritten siRNA off-target
pipeline that
consumes the bindings directly and thus doubles as a reference example for
users wishing to embed RIsearch3 in their own pipelines.

\section{Rationale for a Rust Reimplementation}\label{sec:rationale}

Updating the existing C codebase would have resolved installation friction
but not the absence of a library API or the Python~2.7 dependency. Rust was
chosen because it addresses all three limitations simultaneously.

A \texttt{cargo build -{}-release} produces a statically-linked binary with no
runtime dependencies, solving the Makefile-and-tarball distribution problem.
Rust's ownership model eliminates memory-safety defects without a garbage
collector, preserving the predictable, low-latency performance expected of a
bioinformatics search kernel. The PyO3 framework provides first-class Python
interoperability without writing C extension modules; combined with Maturin,
it enables compiled platform wheels distributed via PyPI, so the Python API
is available through a standard \texttt{pip install}. Rust's strong type
system made the reimplementation tractable: the compiler enforces invariants
that would otherwise require extensive runtime testing, reducing the risk of
introducing silent numerical discrepancies relative to the original C code.

\section{RIsearch3 Core Implementation}\label{sec:core}

RIsearch3 reimplements the suffix-array seed-and-extend algorithm of
RIsearch2~\citep{alkan2017risearch2} in Rust. The two-stage scheme is
preserved without modification: a suffix array of the concatenated target
sequences (with the reverse-complement strand stored explicitly) is
traversed in parallel with a per-query suffix array to locate maximal seed
matches, and each seed is then extended by dynamic programming under the
simplified nearest-neighbour energy model of~\citet{wenzel2012risearch}.
Match identity follows the parallel-direction trick of
RIsearch2~\citep[Fig.~1B]{alkan2017risearch2}, with $G{-}A$ and $U{-}C$ identities
counted as matches so that $G{-}U$ wobble pairs are admitted.

The rewrite focuses on engineering rather than algorithmic change. Suffix-array
construction is delegated to the \texttt{libsais} library, replacing the
\texttt{libdivsufsort} library used by RIsearch2; an optional OpenMP build
provides parallel index construction. Search is parallelised with
Rayon~\citep{rayon} across seed groups, with each worker holding its own
dynamic-programming context to avoid contention. The DP extension uses an
X-drop early-termination heuristic, evaluates the energy model inline rather
than through precomputed lookup tables, and represents the forward and reverse
strands through Rust const generics so that the compiler specialises both code
paths separately. The crate uses the jemalloc allocator. Both energy parameter
sets supported by RIsearch2 (\texttt{t04} and \texttt{t99}, derived from the
Turner nearest-neighbour parameters) are retained and selected at run time
(see Section~\ref{sec:bindings}).

Behaviour preservation is enforced by a parity test suite. Integration tests
compare RIsearch3 output against the original C implementation across seed
length and position constraints, mismatch settings, extension parameters,
both energy parameter sets, $G{-}U$ wobble handling, and the optional banding
mode. Outputs match bit-for-bit on the regression corpus. Migration risk is
therefore minimal: existing analyses can adopt RIsearch3 without
re-validating downstream results.

\section{siRNA Off-Target Discovery Pipeline}\label{sec:pipeline}

The siRNA off-target discovery pipeline is a full reimplementation of the
workflow described in \citet{alkan2017risearch2}, ported from Python~2.7 to
Python~3.14, restructured as a modular package, and accelerated through
vectorised DataFrame operations and multi-core parallelism.

\subsection*{Invocation and configuration}

The pipeline exposes two subcommands: \texttt{off-targets}, which executes
the core analysis, and \texttt{accessibility}, which pre-computes RNA
binding-site opening-energy profiles using RNAplfold~\citep{lorenz2011vienna}.
All parameters---RIsearch energy threshold, seed specification, thermodynamic
saturation parameters $\alpha$ and $\gamma$, accessibility window settings,
and paths to query, transcriptome, and on-target files---are declared in a
single YAML configuration file and validated at startup against a typed schema.
YAML-driven configuration makes runs reproducible and shareable without
relying on shell history. Individual subcommands may also be invoked
independently to support staged workflows.

\subsection*{Pipeline stages}

The four-stage model of \citet{alkan2017risearch2} is preserved. In the first
stage, siRNA--target interaction predictions are generated by calling the
RIsearch3 search engine directly through its Python bindings
(Section~\ref{subsec:pybindings}), returning results as a Polars DataFrame
in the same process with no intermediate files on disk. In the second stage,
predicted binding sites are intersected with a transcriptome annotation (GTF
or BED) to retain sites overlapping expressed features and to assign
position-specific abundance values. Intersection is performed in-memory using
an NCLS interval index partitioned by chromosome and strand, with
chromosome--strand pairs distributed across a thread pool; no external tools
such as \texttt{bedtools} are required. In the third stage, hybridisation
energies are adjusted by binding-site opening energies pre-computed with
RNAplfold (default window $W = 80$, maximum base-pairing span $L = 40$,
matching the parameterisation of \citet{alkan2017risearch2}), and the
partition function
%
\begin{equation}
  Z = \sum_{i \in \mathcal{I}} A_i \, e^{-\beta (E'_i + O_i)}
  \label{eq:partition}
\end{equation}
%
\noindent is evaluated as a single vectorised \texttt{group\_by} aggregation
in Polars, where $A_i$, $E'_i$, and $O_i$ denote the abundance, adjusted
hybridisation energy, and opening energy of site $i$, as defined in
\citet{alkan2017risearch2}. Per-transcript off-targeting probabilities
$p_{\mathrm{off},j}$ and the aggregate off-targeting potential
$P_{\mathrm{OFF}} = 1 - p_{\mathrm{on}}$ are then computed as column
operations on the resulting DataFrame. Parametric sweeps over $\alpha$,
$\gamma$, and $\theta$ are resolved in a single aggregation pass rather than
repeated sequential iterations. In the fourth stage, results are written
incrementally as each siRNA completes, in TSV, CSV, or Parquet format.

\subsection*{Parallelism and memory}

When processing a directory of per-siRNA prediction files, the pipeline
distributes work across a configurable process pool. A spawn-based
multiprocessing context is used to avoid interaction with the Rayon thread
pool used internally by Polars. The transcriptome annotation is loaded once
into Arrow IPC format and memory-mapped into each worker process via the
operating-system page cache, keeping peak memory proportional to a single
transcriptome copy regardless of worker count. Prediction files are parsed
lazily so that only filtered, selected columns are materialised; output is
streamed to disk incrementally throughout a batch run.

\subsection*{Backward compatibility}

Setting \texttt{legacy\_format:~true} in the configuration produces output
that is bit-for-bit identical to the original Python~2.7 pipeline, verified
by golden regression tests in the repository. Existing downstream analyses
require no modification to adopt RIsearch3.
